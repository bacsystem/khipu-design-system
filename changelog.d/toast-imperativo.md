### Added
- **`toast` imperativo** (`feedback/toast`): `toast.ok | aviso | error | info | promise | cerrar` se llama desde cualquier parte, sin hooks (manejadores, renderizadores de columna, funciones sueltas); mismas firmas que `useToast()`, que ahora devuelve ese mismo objeto. Va sobre un almacén del módulo (`createToastManager` de base-ui) al que se suscribe `ToastProvider`. Antes de que el proveedor se monte las llamadas esperan en una cola de 5 (`lib/cola-toast`, se descartan las más antiguas); durante el SSR de un componente cliente no hacen nada, para no filtrar avisos entre peticiones (`toast` es código de cliente: desde un Server Component o una server action no se puede llamar). `error` es `priority: "high"` (`role="alert"`, assertive) y el resto polite. El visor se centra bajo `md` y queda abajo a la derecha desde `md`, siempre sobre `--khipu-reserva-inferior`. Las llamadas devuelven el id del aviso (`cerrar(id?)`, sin id cierra todos).

### Changed
- **Si usas la CLI (`khipu add toast`)** se copia también `lib/cola-toast`. `useToast()` ya no exige estar dentro de un `ToastProvider` (sin él, los avisos esperan en la cola). **Un solo `ToastProvider` por app:** ahora comparten el almacén del módulo, así que con dos cada aviso sale dos veces (antes cada uno tenía el suyo); en desarrollo se avisa en consola.
- `toast.promise` ya no tumba la app: base-ui cambia el tipo del aviso a `loading`/`success`, que el visor no conocía (React #130, también en 0.8.0). `loading` se pinta con `Spinner` y tono info, `success` como ok y un tipo desconocido como info. La promesa que devuelve no deja un rechazo sin capturar.
